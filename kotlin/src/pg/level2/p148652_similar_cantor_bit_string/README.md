## 접근
- 처음에는 cantor를 직접 만들고 있었다. 근데 배열 크기가 최대 5^20이라는 걸 알았음에도 Int의 범위에 속하지 못한다는 생각을 못했다. 문제를 풀다가 Long범위라는 걸 알고 다시 생각했다...
- 배열크기가 Long 범위인 데이터형, 자료구조가 있는지 알아보니 없었다. 
- gpt가 그게 궁금한거면 이 문제 푸는거 아니냐고 했다. 그러면서 l,r의 범위만 파악해서 구하면 된다고 했다.
- 나는 n번째를 어떻게 구현하는지 알고 있다. 그리고 5분할해서 각 섹션의 범위 인덱스 값을 구하는 법도 안다. 
- 그럼 재귀로 역산해서 내려가는 거다. 
- 이후로 머리가 잘 안돌아 간다.. 
- l은 n번째 중에는 5개 섹션 중 어느 구간인가, n-1번째 중에서는 어느 구간인가 .. 2번째중에서는 까지 내려감.
- cantor(n)의 1의 개수는 4^n임.
- 5section시 각 section(3이아닐때) 1의 갯수는 5^(n-1)*4

- 여기서부터 연결이 잘안됨. 
- l,s까지의 1의 개수를 구하고 빼면된다는 힌트를 얻음.
- l까지 1의 개수를 구하는 공식을 만들어봄, sum을 구하기
- n번째의 몇번째 section인가 파악하고 그 전 section까지의 1을 구하는 공식을 사용해서 sum에 더하기 
- n-1번째의 몇번째 section인가 파악하고 위와 동일 
- 
- n=2일 때 3번째면 그 다음은 어디든 0이므로 의미가 없다 인줄 알았는데.
- 맨 처음 문제볼 때 생각한대로 3번째 구간은 항상 0 임 

- claude 가 준 힌트
- Int 오버플로. 5의제곱(pow)에서 j를 곱할때 발생 가능성 고려해야함.
- count(n, x+1)을 구하고 있다. r이 마지막 값이면 n의 범위+1이다. 이때 고려해서 count 값을 넘겨야함.

- 고민해볼 점 : 처음에는 내가 구조를 짰지만 이후 자잘한 이슈를 
ai를 통해 예제를 만들고 이걸 pass하면서 풀었다. ai가 없으면 만들기 어려운 상황도 있던데 그런 케이스도 고려하는 힘을 길러야 한다. 
배운 점 => 예제를 다양하게 생각해보는 것도 문제를 푸는데 도움이 된다.
배운 점 => count(r)을 하면 r값이 1인지는 확인이 안된 다는 것. 
배운 점 => count(r+1)로 했을 때 r+1이 비트열을 넘어갈때 고려해야한다는 것. 
배운 점 => 정수를 명시적 데이터없이 선언하면 Int임. Int 범위에 들어갈지도 고민해야함.
배운 점 => 매직 넘버 상수화(파일 최상단 또는 companion object로 해도됨)

## 복잡도
- 시간: O(n) — 레벨마다 섹션 5개만 확인하므로 안쪽 반복은 상수. n ≤ 20이라 매우 빠름.
- 공간: O(n) — sectionInfo 배열.
